# 自动编辑审核流水线

## 目标

开发、内容编辑和中间复核全部自动完成。每次修复或更新只执行一次统一审核；审核无阻断项后，自动继续提交、PR、CI、合并、版本标签、生产部署与线上验收。自动流程永远不能把自身描述为外部学者或人工同行评审。

## 状态边界

```text
candidate → edited → reviewed → published
```

- 自动编辑器只能执行可重复、可审计的安全规范化，或把内容推进到 `reviewed`。
- 内容状态推进仍遵循编辑与复核门禁；代码自动发布只包含已经处于 `published` 的内容，绝不自动提升候选记录。
- 合并 `main` 和部署由统一审核通过后的受保护自动流程完成，不绕过 CI 或分支保护。
- 现有迁移记录使用 `automated-migration-review/v1` 标明自动复核身份。
- 来源不足、关系证据不足、候选内容泄漏或回归测试失败都会阻断审核包。

## 自动阶段

1. **安全编辑**：去除首尾空白、去重标量数组、同步引用涉及的来源ID，并规范自动复核身份。
2. **结构与引用**：运行Zod、引用端点、内容层级、媒体、关系方向、争议说明和候选隔离检查。
3. **证据质量**：按原典、同行评审、学术专著、专家百科和参考数据集分级；识别过于通用的引用主张及缺失责任者。
4. **覆盖治理**：验证210人发布清单、180个新增人物映射、地区与时代统计及精确公开数量。
5. **批次生产治理**：验证六批共180个生产任务、工作依赖、重试预算、来源核验与装配门禁。
6. **媒体治理**：验证210份媒体卡片、公开许可来源、项目艺术形象标注、原图与缩略图文件完整性。
7. **工程回归**：ESLint、TypeScript、生产构建、数据测试、分包预算、桌面和移动端Playwright。
8. **统一审核报告**：生成JSON与Markdown，给出阻断项、警告、测试阶段、分支、提交和自动发布许可。

确定性检查不能独立证明哲学主张为真。每批内容仍由执行任务的自动审阅代理进行来源阅读、跨文化偏差检查和反例检索；该过程的发现必须写回引用、内容或审核报告，不能只留在对话中。

## 命令

```bash
# 应用安全、机械的自动编辑
npm run content:edit

# 不修改文件，只验证是否仍需要自动编辑
npm run content:edit:check

# 从公开学术页面的citation metadata补全缺失作者；无法验证时保持为空并报告
npm run content:enrich-sources

# 内容、代码和构建审核；浏览器阶段标为未运行
npm run review:automated

# 自动修复后执行非浏览器审核
npm run review:fix

# 自动发布前必须执行的完整统一审核
npm run review:full
```

报告生成到 `artifacts/review/latest.json` 和 `artifacts/review/latest.md`。该目录不提交版本库。GitHub Actions 对每个 PR 只触发一次审核：核心审核、桌面浏览器和移动浏览器并行运行，再由必需的 `validate` 汇总门禁统一判定；合并后的 `main` 只复跑核心审核，不重复已经通过的浏览器套件。报告保存30天。

## 自动发布门禁

审核报告必须包括：

- 自动结论：阻断或允许自动发布；
- 本批实体、关系和来源数量；
- 来源与语义警告及示例条目；
- 所有工程阶段状态；
- 页面视觉与已知风险；
- 明确声明自动发布和部署是否被允许。

存在阻断项时，不创建发布提交、不合并 `main`、不部署；无阻断项时自动完成剩余发布流程。candidate、edited和reviewed内容不会因为代码发布而变成published。
