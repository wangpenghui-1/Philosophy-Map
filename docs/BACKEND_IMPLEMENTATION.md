# 后端实施与运行说明

## 当前交付

本阶段建立了可运行的模块化后端基础，同时保持现有公开站不依赖数据库：

- PostgreSQL/Drizzle 迁移包含会员验证令牌、pgvector、trigram、内容版本不可变触发器、用户数据RLS策略和Outbox。
- 静态兼容Repository只读取构建器生成的published快照；candidate不会进入公共API或AI检索。
- 已实现目录、实体、搜索、图谱、旅程、来源、Atlas Snapshot和OpenAPI端点。
- `/chat`提供匿名与登录用户都可使用的对话界面；无数据库时为临时模式，配置数据库后按账户或匿名会话隔离保存消息、引用快照、模型运行、延迟、Token与费用估算。
- OpenAI适配器使用Responses API并固定`store: false`；没有模型配置时使用站内证据的抽取式回答。
- AI消息使用SSE返回`ack`、`retrieval`、`text.delta`、`citation`、`usage`、`done`与`error`；模型输出只要存在越界引用或任一事实段落没有证据标记，就退回可复现的抽取式答案。
- 已实现会员邮箱验证、密码登录与重置、数据库会话、设备远程注销、个人设置、收藏、阅读/旅程进度、数据导出与账户硬删除。
- 已实现候选版本创建、乐观并发控制、审核状态机、发布审计和发布Outbox。

没有配置外部服务时，`npm run dev`、构建和现有页面仍使用静态兼容模式。

## AI 对话与评测

`npm run ai:eval`运行固定中文哲学问题集，覆盖有材料问答、历史影响、人物思想、知识库缺失拒答和引用完整性。该命令不调用付费模型，先验证检索、拒答与引用门禁；生产模型上线前还应在预发布环境运行同一数据集的供应商评测并记录模型版本。匿名用户每小时默认12条消息、登录用户60条；配置Upstash Redis后限额跨实例共享，未配置时只提供单实例降级限流，不能视为生产就绪。

对话所有权只能是`user_id`或匿名会话摘要二选一。数据库RLS同时读取事务内`app.user_id`或`app.anonymous_session_hash`，列表、读取、删除、追加消息和取消操作都重新验证所有权。取消是当前运行实例内的尽力中止；客户端断线后可通过会话详情读取已经完成并持久化的最终消息。

## 长期记忆与隐私生命周期

长期记忆默认关闭。用户在账户中心打开开关后，仍需逐条明确保存；系统不会从对话中自动生成持久记忆。确认记忆最多取8条，只用于语言、解释深度、学习目标和关注重点，并以`<personalization>`数据区发送给模型，不能作为哲学事实证据。每次读取会更新时间并写入审计事件，关闭开关后立即停止读取。

用户可在账户中心查看、修改和逐条硬删除记忆。政治立场、宗教身份、健康状况、病史等敏感属性在API层拒存。`memory_embeddings`按`user_id`启用RLS并随账户级联删除，目前不主动生成向量；只有实际负载证明结构化排序不足时才启用。数据导出包含账户、同意记录、会话元数据、收藏、进度、记忆及其派生数据、对话、引用、模型运行和用量，但明确排除密码与会话Token摘要。

## 环境与命令

复制`.env.example`到本地环境文件并只填写需要启用的服务。真实密钥不得提交。

```bash
npm run db:generate
npm run db:migrate
npm run db:shadow:check
npm run db:shadow:apply
npm run backend:shadow-check
npm run worker:run-once
```

`db:shadow:check`只检查生成快照是否可以安全导入。`db:shadow:apply`才会连接数据库，并且只导入构建器已经判定为published的记录。相同实体版本不会被原位覆盖；内容变化必须增加版本号。

## 管理员登录与内容后台

管理后台入口为`/admin/login`。未配置数据库时，只在`127.0.0.1`或`localhost`提供只读预览；该身份不能创建、编辑、审核或发布内容。正式环境必须先执行迁移，再通过一次性环境变量创建首个owner：

```bash
ADMIN_BOOTSTRAP_EMAIL="owner@example.com" \
ADMIN_BOOTSTRAP_PASSWORD="使用密码管理器生成的长密码" \
npm run admin:bootstrap
```

初始化命令不会输出密码，也不会默认覆盖已有凭据。确需轮换现有owner密码时，单次设置`ADMIN_BOOTSTRAP_FORCE=1`。登录会话使用随机Token，数据库只保存SHA-256摘要；密码使用带随机盐的scrypt哈希。连续失败八次后锁定十五分钟。

首个后台版本包含总览、内容筛选、candidate创建、草稿编辑和状态推进。第二阶段补充了发布质量门禁、版本历史、从已发布版本创建后继修订、撤回当前公开版本和回滚到历史发布版本。已发布记录本身始终不可原位修改；撤回与回滚只切换实体的公开版本指针，并写入发布事件、审计和Outbox。公开指针变更还会校验页面加载时看到的版本，避免管理员并发操作时覆盖彼此。

发布质量门禁当前检查摘要、正文分区和来源绑定；深入内容与人物引文以提醒呈现。门禁是后续来源工作台和逐段引用核验的基础，不替代学术复核。

内容版本详情已经提供逐段引用工作台：管理员可为每个正文段落选择已发布来源，填写精确定位和该来源支持的主张。保存时服务端会拒绝字段残缺或指向不存在来源的引用；标准与深入内容若仍有未绑定来源的正文段落，将无法发布。未配置数据库时，同一界面以只读方式展示Git快照中的引用，便于验收数据结构而不会形成可写后门。

来源资料库入口为`/admin/sources`，支持候选创建、元数据编辑、复核发布、不可变历史版本和从已发布来源创建后继修订。来源发布前必须具备标题、责任主体、类型、出版信息、语言，以及URL、DOI或ISBN中的至少一种持久定位。发布后如果包含URL，会通过Outbox交给Worker执行受限的HEAD检查；Worker拒绝非HTTP协议和解析到本地、链路本地或私网地址的目标，避免把链接检查变成SSRF入口。链接失败会沿用Outbox重试与失败状态。

关系图谱工作台入口为`/admin/relations`，支持创建候选关系、编辑解释与引用、学术复核、发布、不可变版本历史，以及从已发布关系创建后继修订。数据库模式会显示关系两端当前公开版本的实体标题，而不是内部UUID。关系发布门禁要求至少一条已发布来源、精确定位和支持主张；`thematic-resonance`必须是非方向关系，`disputed`关系必须明确写出争议边界。关系正文与引用在同一事务中保存，发布操作同时更新公开指针、审计记录和Outbox，后续快照与图谱索引只能消费已发布版本。

思想旅程工作台入口为`/admin/journeys`，现有八条前端旅程在无数据库时可作为只读快照核验。数据库模式支持候选创建、结构化节点与镜头编辑、证据关系／主题比较转场、审核发布、不可变版本历史和后继修订。发布门禁会检查5至7个节点、开场与结语、叙事字段、阅读时长、镜头范围、人物公开状态及转场端点；历史转场必须引用连接前后人物的已发布关系，已有历史关系时不得降格成无证据的主题比较。发布在同一事务内更新公开指针、审计和`journey.published` Outbox事件。影子导入现在也会幂等导入现有旅程与节点，公共播放器仍读取版本化静态定义，数据库故障不会影响访问。

媒体资产中心入口为`/admin/media`。无数据库时会把现有人物图像作为只读公开快照展示；数据库模式通过S3兼容接口生成15分钟有效的预签名URL，浏览器将文件直接上传到对象存储，应用服务器不转发大文件。上传申请同时固定MIME、字节数和SHA-256校验值，完成接口通过HEAD核对对象后将资产放入quarantined隔离状态，并写入`media.scan.requested` Outbox。独立Worker调用HTTPS恶意文件扫描服务；只有clean结果才能推进为ready并触发`media.asset.ready`，扫描未配置、超时或返回异常时不会公开对象。允许格式限定为常见图片和音频，单文件上限250MB；授权状态、真实性、署名、许可证、来源URL、替代文本和绑定实体均可独立维护。归档采用软删除且不立即删除对象，避免破坏已发布内容；对象存储必须保持私有，对象生命周期清理必须由生产运行手册中的保留策略控制。

## API 边界

公共API根路径为`/api/v1`，契约入口为`/api/v1/openapi`。公共读响应带CDN缓存策略；Atlas Snapshot支持ETag。

后台写路径为`/api/admin/v1`。内容版本更新必须携带读取时返回的`If-Match`，否则返回428；版本过期返回412。发布只能从reviewed推进，并在同一事务中写入发布事件、审计事件和Outbox。当前Worker已经识别发布、撤回和回滚事件，但只记录待刷新投影；在对象存储和正式发布任务接通前，数据库指针变化不会直接覆盖Git生成的公开静态快照。

个人数据端点必须持有`atlas_session`数据库会话Cookie。普通会员从`/account/register`注册并完成邮箱验证；验证和密码重置令牌只以SHA-256摘要保存且只能消费一次。管理员入口仍与会员入口分离。未来OIDC供应商必须接入现有`AuthPort`，不能绕过账户状态、角色和会话撤销规则。

## 数据安全边界

- PostgreSQL必须使用独立应用角色；表所有者会绕过普通RLS，不能作为生产应用连接角色。
- 应用角色访问用户表时应在事务中设置`app.user_id`，RLS策略以该值校验所有权。
- 高权限账户的MFA、邮件/OAuth供应商、Redis限流、Inngest托管接入和对象存储仍需要部署环境配置。
- 账户删除会级联删除会话、消息、记忆、收藏与进度；审计事件保留但不保存认证凭据。
- 音频、实时语音和原生移动端尚未进入本阶段运行范围，数据库与API只预留兼容边界。

## 生产运行与灾备

- 公共存活探针：`GET /api/health/live`；依赖就绪探针：`GET /api/health/ready`。
- 管理员运行页：`/admin/system`；详细API需要`system:operate`，显示关键集成、Outbox和24小时AI费用。
- `REQUIRE_PRODUCTION_SERVICES=1`时，数据库、Redis、媒体存储、邮件、扫描、AI和Sentry缺失或异常会使ready返回503；公开静态快照仍独立可读。
- 备份与恢复策略位于`infra/backup-policy.json`和`infra/runbooks/`，目标RPO不超过24小时、RTO不超过4小时。
- `npm run backup:verify`只检查策略；带绝对归档路径的`backup:verify:archive`检查时效、SHA-256和归档可读性。
- `npm run restore:drill`默认只输出计划；执行模式只接受空的、带`atlas_restore_`前缀且不同于生产的临时数据库，不会清库或自动删除目标。
