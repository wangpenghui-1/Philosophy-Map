# ADR 0004：管理后台先采用项目自有数据库会话

- 状态：已接受
- 日期：2026-08-06

## 背景

项目已经通过`AuthPort`隔离认证实现，并拥有自有`users`、`sessions`和`user_roles`表。当前稳定版NextAuth为v4，而面向新App Router接口的v5仍为beta。为了上线首个可维护的管理后台，不应把核心权限边界绑定到beta API，也不应为了本地演示添加可写后门。

## 决策

管理员首版采用项目自有数据库会话：

- 密码使用带随机盐的scrypt哈希；数据库不保存明文密码。
- 浏览器只持有随机会话Token；数据库仅保存Token的SHA-256摘要。
- 会话Cookie使用`HttpOnly`、`SameSite=Strict`，HTTPS环境增加`Secure`。
- 账户连续失败八次后锁定十五分钟。
- 首个owner只能通过一次性CLI环境变量初始化，不提供公开注册。
- 未配置数据库时，只有loopback地址可进入本地只读预览；该身份不能写入数据。
- 页面可见性不是权限边界，所有写接口继续通过`AuthPort`和领域权限校验。

## 后续兼容

未来接入OIDC、企业SSO或稳定版Auth.js时，实现新的`AuthPort`适配器并复用现有用户、角色和审计域。数据库会话与权限模型保持不变，管理页面和业务API无需感知供应商差异。
